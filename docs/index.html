¿Qué es y para qué sirve?

El conector Tenable Security Center permite que el agente de Ruvic consulte las vulnerabilidades de tu red, los activos más expuestos y sus hallazgos, y lance escaneos ya definidos. Puedes pedirle cosas como:

  • "¿Qué vulnerabilidades críticas con exploit público tenemos y en cuántos equipos?"
  • "¿Cuáles son los 10 servidores más expuestos de la red 10.0.0.0/24?"
  • "Lanza el escaneo semanal de la DMZ."

Operaciones soportadas:

OperaciónQué hace
vulns.listVulnerabilidades agrupadas por plugin, con número de activos afectados
assets.listActivos con puntaje y conteo por severidad
findings.listHallazgos por host, plugin o severidad
scans.listEscaneos definidos
scans.launchLanza un escaneo ya definido (escribe)
Lanzar un escaneo genera tráfico real Las consultas son de solo lectura. Lanzar un escaneo ejecuta pruebas contra los equipos definidos en ese escaneo.

Prerrequisitos

  • Tenable Security Center 5.13 o superior, con API Keys habilitadas.
  • Un usuario dedicado con rol Security Analyst (o personalizado) y acceso a los repositorios necesarios.
  • Conectividad HTTPS desde la plataforma Ruvic hasta la consola.

Configuración en el fabricante

Vas a habilitar las API Keys y generarlas con un usuario dedicado.

  1. Habilita las API Keys.

    Como administrador, ve a System → Configuration → Security y activa Allow API Keys.

  2. Crea el usuario dedicado.

    En Users → Users → Add, crea "ruvic-api" con rol Security Analyst y los repositorios que deba consultar.

  3. Genera las llaves.

    Inicia sesión como ese usuario y ve a My Profile → API Keys → Generate API Key. Copia la Access Key y la Secret Key.

Permisos requeridos

Principio de mínimo privilegio: el usuario solo necesita lo siguiente.

PermisoPara qué lo usa el conector
Acceso a repositoriosConsultar vulnerabilidades, activos y hallazgos
Lanzar escaneosEjecutar escaneos ya definidos con launch_scan

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Tenable Security Center y pulsa Configurar. Diligencia el formulario con los valores de la sección anterior:

Campo del formularioValor
URL de Tenable Security CenterURL de la consola, ej. https://tenablesc.miempresa.com
Access KeyAccess Key generada. Se guarda cifrada
Secret KeySecret Key generada. Se guarda cifrada
Verificar certificado SSLActívalo siempre, salvo certificados autofirmados en redes de confianza
Timeout de conexión (segundos)Opcional; 30 segundos por defecto

Guarda y pulsa Probar conexión: la plataforma valida las credenciales y el acceso.

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder con éxito y la tarjeta debe quedar en estado Configurado.

  2. Prueba mínima con el agente.

    Abre una conversación nueva y pídele:

    "¿Cuántas vulnerabilidades críticas hay en Tenable y cuál afecta a más equipos?"

    El agente debe responder con datos reales de la consola. No le pidas lanzar escaneos durante la prueba.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"API Keys inválidas o sin permiso" (401/403)Llaves mal copiadas, regeneradas, o API Keys deshabilitadas en Configuration → Security.
Resultados vacíosEl usuario no tiene acceso al repositorio con esos datos. Revisa sus repositorios asignados.
"ip_range inválido"Usa una IP, un rango a-b o un CIDR (ej. 10.0.0.0/24).
"Error de certificado SSL"La consola usa un certificado autofirmado. Instala uno válido o desactiva la verificación en una red de confianza.

Preguntas frecuentes y notas de seguridad

¿Sirve para Tenable en la nube?

No. Para Tenable Vulnerability Management (cloud.tenable.com) usa el conector Tenable / Nessus (CON-051).

¿El agente puede crear o borrar escaneos?

No. Solo lanza escaneos ya definidos por tu equipo.

¿Qué hago si las llaves se filtran?

Genera llaves nuevas en My Profile (invalida las anteriores) y actualízalas en el formulario.
